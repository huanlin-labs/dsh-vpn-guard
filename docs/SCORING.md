# 评分规则 v2（0.5.0）

本文件说明 0.5.0 的评分口径。目标是让“没测到”与“测到且很差”分开，避免轻量检测或单个来源抖动导致 AI 分数大幅跳动。

## 1. 全量快照是评分的唯一来源

- 轻量检测只刷新运行态（Clash、端口、出口 IP、进程等），不会写入或清空 AI / 信誉评分。
- 完整全量成功后，结果才会替换 `last-full.json` 并追加历史。
- 不完整的全量会保留上一次完整结果，并在 UI 标记“本次全量不完整”。
- 插件重启后从 `last-full.json` 恢复最近一次完整结果，首次轻量检测不会把评分清空。

完整全量的判定（`scores.meta.complete === true`）：

- AI 来源成功且有结果；
- 出口身份来源有证据；
- 网络来源有证据；
- 证据覆盖率达到 75% 以上。

## 2. 缺失数据不再变成低分

每个维度独立返回 `null` 或分数：

- 没有证据 → `null`，UI 显示“— / 证据不足”；
- 有证据但只有单一来源 → 可显示分数，但置信度标为“低”；
- 有多个来源且覆盖完整 → 置信度“中”或“高”。

整体分只对存在的维度按权重重新归一化，不会把缺失项当成 0 分。

## 3. 稳定性

完整全量会计算最近 3 次完整结果的 AI 中位数与整体中位数：

- KPI 主值使用 `aiStable`（3 次中位），旁边保留本次原始值；
- 档位变化需要连续 2 次同方向确认；未确认时保留上一次稳定值，并在 AI 页标注“变动待确认，暂按前值”；
- 历史记录保存 `scoreVersion`、`scoreMeta`、`stableAi`、`stableOverall`；
- 变化原因在 AI 页显示：正常波动 / 来源缺失或覆盖下降 / 来源结论变化；
- 评分规则版本为 `v2`，不同版本的旧历史不会参与中位数计算。

## 4. 仍不声称的事

当前 AI 分数仍主要来自 `ipjudge` 的单来源结果，`claude-ipcheck` 用于信誉与滥用证据。它还不是“多厂商独立源投票”；真正的多源聚合是下一阶段（第 3 项）的工作。
